# 15 — Accessibility & Internationalisation

Accessibility here is not a compliance chore. `RN-01`/`RN-02` establish that proctoring controls **disproportionately harm** students with disabilities, students using assistive technology, and students on unstable connections. An inaccessible exam is not merely unlawful; it will corrupt the measurement we are trying to take.

---

## 1. Target

**WCAG 2.2 level AA** across authoring, classroom, exam and results surfaces, verified by automated checks in CI **and** a manual audit signed off by someone who did not build it.

### 1.1 WCAG 2.2 additions that specifically bite an assessment product
The 2.2 additions are not abstract here:

| Criterion | Level | Why it matters here |
|---|---|---|
| **2.4.11 Focus Not Obscured (Minimum)** | AA | A sticky exam header or a floating save indicator must never cover the focused control. In a one-question-at-a-time exam the focused element *is* the whole task. |
| **2.5.7 Dragging Movements** | AA | Our block drag handles and vector draggability in sims need keyboard alternatives. Drag-only interaction fails this criterion outright. |
| **2.5.8 Target Size (Minimum, 24×24)** | AA | Exam answer options and the question palette must be finger-sized for students on small devices. |
| **3.2.6 Consistent Help** | A | Support entry points in a consistent place across the exam surface. |
| **3.3.7 Redundant Entry** | A | A student must never have to re-enter the same information twice in one process. Directly relevant to autosave and resume. |
| **3.3.8 Accessible Authentication (Minimum)** | AA | MFA must not require cognitive-function-test transcription. TOTP codes are permitted precisely because they satisfy this. |

### 1.2 The hard cases in this product
| Surface | The hard part |
|---|---|
| Exam runtime | Fullscreen + pointer lock + copy-blocking are, individually, accessibility hazards. Every one has a relaxation path (`09` §8) |
| Block editor | A rich-text editor is one of the hardest things to make accessible. Keyboard block movement, no traps, real names on every handle |
| Simulations | Canvas is invisible to a screen reader. Every sim must ship a text alternative describing what the visualisation shows, and a keyboard path to every control |
| KaTeX | Must emit **MathML**, not just visual glyphs |
| Timed exams | A screen-reader user needs the per-question timer announced politely, not aggressively, and never in a way that interrupts a question mid-read |
| Drag interactions | `2.5.7` — every drag has a keyboard equivalent with the same outcome |
| Data tables | Real `<caption>`, `<th scope>`, and a non-visual path to the same information |

## 2. Non-negotiable rules

1. **Semantics first.** Native elements wherever they exist. `div` with a click handler is a defect, not a shortcut.
2. **No keyboard traps.** Including in modals — a focus trap must have an escape, and the exam's policy modals must never trap a student who needs to reach the browser chrome.
3. **Focus is never lost.** Route changes, autosave completions, and sim `readyForInput` all move focus deliberately. Announce with a polite live region, never steal focus for a background update.
4. **Live regions are used sparingly.** A countdown that announces every second is unusable. Announce at meaningful thresholds (10 min, 5 min, 1 min, 30 s) and on state changes.
5. **Every interaction is keyboard-operable**, in a documented and stable order.
6. **Colour is never the only signal.** Pass/fail, severity, distractor feedback and integrity severity all carry text or an icon as well.
7. **Contrast ≥ 4.5:1** for text and ≥ 3:1 for UI components and graphical objects, in both themes and in `forced-colors` mode.
8. **Reduced motion is honoured.** `prefers-reduced-motion` disables auto-playing simulations, parallax, and non-essential transitions — and the exam surface's own animations.
9. **Text can be resized to 200%** and reflowed at 320 px width without loss of content, on every route including the exam.
10. **Alt text is required at authoring time**, not flagged later (`05` §5).

## 3. Accommodations are the product's accessibility commitment

`INV-ACC-1` and `09` §8. The distinction we hold firmly:

| Relaxation | Effect |
|---|---|
| `DISABLE_POINTER_LOCK` | No lock, no lock-loss events |
| `ALLOW_TAB_SWITCH` | Screen readers, magnifiers, translation tools work; tab hides are not violations |
| `ALLOW_COPY_PASTE` | Paste works, because paste-blocking breaks switch access and some magnifiers |
| `ALLOW_FOCUS_LOSS` | Focus watchdog relaxed |
| `EXTRA_TIME_PERCENT` | Extends all deadlines, recorded as an audited `DEADLINE_EXTENDED` |
| `BREAKS_ALLOWED` | Server-approved pauses that actually stop the clock |

Accommodations are granted in two clicks, **including during a live exam**, produce zero violations, and are recorded in an auditable register — because an institution needs the record, and because making the honest exception cheap is the only way to stop teachers choosing "no deadlines at all" instead.

## 4. Testing accessibility

| Layer | Tool | Cadence |
|---|---|---|
| Component | `axe-core` in Vitest via jsdom, plus Testing Library queries by role | Every PR |
| Route | `axe-core` in Playwright against seeded pages | Every PR, key routes |
| Editor | Manual scripted keyboard walkthrough | Every PR |
| Exam surface | Automated axe **plus** a screen-reader pass (NVDA/VoiceOver) | Every release |
| Simulations | Per-sim keyboard-reachability assertion in the conformance matrix | Every build |
| Full audit | Manual WCAG 2.2 AA audit by an independent reviewer | P13, and before GA |

**Simulations are the biggest risk.** A canvas-based sim with no text alternative passes every automated check and is completely unusable with a screen reader. So the conformance matrix asserts that every registered sim declares a `textAlternative` and that every control is keyboard reachable — the machine gate, not a reviewer's memory.

## 5. Internationalisation

### 5.1 Scope
- **en-GB** primary (the author's spelling, date and currency conventions).
- **en-US** shipped, to prove the framework handles a real locale difference rather than a cosmetic one.
- **One further locale** at GA, chosen to stress the system — a non-Latin script, so we prove the framework does not assume English.
- Content language is a **per-question and per-resource** field from P5, distinct from UI language. A student can take an assessment in one language and use the interface in another.

### 5.2 Implementation
| Concern | Approach |
|---|---|
| Extraction | All strings in typed message catalogues. **CI fails on a hardcoded user-facing string** |
| Format | ICU MessageFormat for plurals and gender. "1 attempt" vs "3 attempts" is not a `+ 's'` |
| Dates, times, numbers | `Intl` with the user's locale and timezone. Deadlines always render in the **user's** zone, with an explicit timezone label |
| Right-to-left | Logical CSS properties only (`margin-inline-start`, never `margin-left`). Layout checked with a RTL locale in CI |
| Text expansion | Layouts tested at +30% string length; no fixed-width text containers |
| Content language | Per-resource and per-question; a missing translation falls back to the author's language with a visible notice, never a blank |
| Numbering | Exam question numbering must be **localised correctly** (and "Question 1 of 30" is not the same word order in every language) |
| Fonts | Math and simulation labels must not depend on a system font that lacks coverage |

### 5.3 The traps we are naming in advance
- **Simulations embed English text in canvas.** A sim's labels are drawn, not laid out by the browser. Localising 220 sims is a real cost. Decision: the manifest declares a `textScale` and the sim reads strings from a catalogue, but **sim text is English-only in v1**, and this is disclosed. The alternative — 220 × N translations before GA — would delay the whole product for a marginal gain, and the accessibility text alternative (which *is* localised) covers the screen-reader case.
- **Question text is content, not UI.** It is translated by the author, not by us. Fine.
- **Right-to-left inside a physics sim** is meaningless and is not attempted.

## 6. Phase deliverables (P13)

| ID | Deliverable |
|---|---|
| P13-T1 | Automated axe across all key routes in CI; component-level axe in Vitest |
| P13-T2 | Editor accessibility: block handle names, keyboard movement, no traps, focus management |
| P13-T3 | Exam surface accessibility: focus order, live-region policy, `2.4.11` compliance with sticky UI, announcement thresholds |
| P13-T4 | Simulation text alternatives enforced in the conformance manifest |
| P13-T5 | KaTeX MathML output and screen-reader verification |
| P13-T6 | Accommodations UX: grant during a live exam, register, audit export |
| P13-T7 | i18n framework: extraction, ICU, `Intl` dates/numbers, `i18n:check` gate |
| P13-T8 | en-GB + en-US catalogues; RTL layout check in CI; +30% text-expansion tests |
| P13-T9 | **Independent manual WCAG 2.2 AA audit**, findings triaged and remediated, signed off |

**Exit criteria:** automated axe clean on every key route; independent audit signed off with no open AA findings; accommodations provably produce zero violations for a real assistive-technology user in a real screen-reader session; **two** locales (`en-GB`, `en-US`) with no hardcoded strings. **RTL is NOT an exit criterion, because nothing produces RTL text** -- `plans/20-PHASE-PACKETS.md` cut the third locale, and `P13-T8` asked for an "RTL layout check in CI" that would have had nothing to assert on and reported PASS on every run, forever. **A check that cannot fail is worse than no check, because it is read as evidence.** The RTL criterion returns in the same commit that adds a locale with an RTL script, and not one commit before.
